# R031 流程規格

產出日期：2026-06-23

## 1. 目的

R031 用於將指定 `CARRIERID` 從 WIP/STK 或 ZIPA 搬送到 Manual Port。系統收到 ASE 的 R031 COMMAND 後，會先驗證 `LOT_ID`、`CARRIERID`、`WIPNAME`，建立 R031 任務與 inbox；之後由 `R031Walker` 撿取 inbox，依目前 carrier 所在位置決定：

1. 若 carrier 已在 ZIPA 指定 slot，送 ZIPA `DispatchOrder` 到 `REJECT`。
2. 若 carrier 在本地 WIP/STK，建立天車出庫 request，目的地為 `Site#15`。

R031 的 START ACK 由 `R031Walker` 送出；END ACK 由 `ZipStockerEventService` 在後續 ZIP/TO 事件成功時自動比對 open R031 任務送出。

## 2. 主要元件

| 元件 | 職責 |
| --- | --- |
| `R031CommandHandler` | 接收 R031 COMMAND，驗證欄位與 ZIPA/WIP slot，寫入 `robot_in_r031`、`robot_r031_task`、`mqtt_inbox`，回覆 ACK=`OK` 或 `FAIL` |
| `R031Walker` | 排程撿取 R031 inbox，檢查現場狀態，決定送 ZIPA `REJECT` 或建立出庫到 `Site#15`，並回覆 ACK=`START` |
| `ZipStockerEventService` | ZIP/TO 成功事件後，以 carrier 比對 open R031 任務，回覆 ACK=`END` 並更新任務完成 |
| `RobotTaskCommandController` | UI/API 取消 R031 任務時，更新任務為取消並回覆 ACK=`CANCEL` |
| `R031AckHandler` | 接收外部 R031 ACK 並記錄到 `mqtt_message_log` |
| `RobotR031TaskRepository` | 查詢與更新 R031 任務狀態，`findOpen()` 排除 `END`、`FAIL`、`CANCEL` |

## 3. COMMAND Payload

DTO：`R031CommandPayload`

### 3.1 Header

| 欄位 | 說明 | 規則 |
| --- | --- | --- |
| `CMD` | 指令類型 | 固定 `ROBOT` |
| `CMD_ID` | 指令代號 | 固定 `R031` |
| `TID` | 任務交易編號 | 由 ASE 帶入 |
| `ID_DESC` | 指令描述 | 預期 `STK_MOVE_SCH_TO_MANUAL_PORT` |
| `MESSAGE` | 任務內容 | 必填 |
| `RESULT` | COMMAND 來文通常不使用 | 依外部格式 |
| `RESULT_MESSAGE` | COMMAND 來文通常不使用 | 依外部格式 |

### 3.2 MESSAGE

| 欄位 | 型別 | 必填 | 說明 |
| --- | --- | --- | --- |
| `LOT_ID` | String | 是 | Lot ID，同時作為 ACK echo 與找容器 fallback |
| `CARRIERID` | String | 是 | Carrier ID，優先用於比對 ZIPA/WIP 與 `container_main.alias_code` |
| `WIPNAME` | String | 是 | ZIPA type=3 slot name 或 WIP location name |

## 4. R031CommandHandler 流程

1. 從 `MESSAGE` 取出 `LOT_ID`、`CARRIERID`、`WIPNAME` 並 trim。
2. 將原始 COMMAND 記錄到 `mqtt_message_log`，取得 `logId`。
3. 建立 R031 ACK skeleton，固定：
   - `CMD=ROBOT`
   - `CMD_ID=R031`
   - `ID_DESC=STK_MOVE_SCH_TO_MANUAL_PORT`
   - `MESSAGE` echo 原始 `LOT_ID`、`CARRIERID`、`WIPNAME`
4. 若任一必填欄位為空，立即回覆 ACK=`FAIL`，`RESULT_MESSAGE=Missing required fields: LOT_ID, CARRIERID and WIPNAME are required.`。
5. 先查 ZIPA all slots：
   - 只看 `type == 3`
   - `name` 等於 `WIPNAME`
   - carrier 取 `message[1]`
   - 若 `message[1]` 等於 `CARRIERID`，視為驗證通過。
6. 若 ZIPA 找不到該 slot，改查本地 WIP slots：
   - `locationName` 等於 `WIPNAME`
   - `containerAliasCode` 等於 `CARRIERID`
   - 符合則驗證通過。
7. 若 ZIPA 與 WIP 都找不到 `WIPNAME`，回覆 ACK=`FAIL`，訊息為 `WIPNAME not found`。
8. 若找到 slot 但 carrier 不符，回覆 ACK=`FAIL`，訊息為 `CARRIERID mismatched at the given slot`。
9. 驗證通過後寫入或更新 `robot_in_r031`：
   - `log_id = mqtt_message_log.id`
   - `lot_id`
   - `carrier_id`
   - `wip_name`
10. 寫入或更新 `robot_r031_task`：
    - `log_id`
    - `tid`
    - `lot_id`
    - `carrier_id`
    - `wip_name`
    - `raw_message_json`
    - `internal_state = QUEUED`
    - `external_last_result = OK`
    - `external_last_time = now`
11. 寫入 `mqtt_inbox`，priority 固定 `5`。
12. 更新 `robot_r031_task.inbox_id`。
13. 回覆 ACK=`OK`，`RESULT_MESSAGE` 空字串。

## 5. R031 任務資料

### 5.1 `robot_in_r031`

| 欄位 | 來源 |
| --- | --- |
| `log_id` | `mqtt_message_log.id` |
| `lot_id` | `MESSAGE.LOT_ID` |
| `carrier_id` | `MESSAGE.CARRIERID` |
| `wip_name` | `MESSAGE.WIPNAME` |

### 5.2 `robot_r031_task`

| 欄位 | 建立時內容 |
| --- | --- |
| `log_id` | `mqtt_message_log.id` |
| `inbox_id` | 建立 inbox 後回填 |
| `tid` | COMMAND `TID` |
| `lot_id` | `MESSAGE.LOT_ID` |
| `carrier_id` | `MESSAGE.CARRIERID` |
| `wip_name` | `MESSAGE.WIPNAME` |
| `source_zone` | 目前流程未填 |
| `manual_port` | 目前流程未填 |
| `raw_message_json` | R031 `MESSAGE` JSON |
| `internal_state` | `QUEUED` |
| `external_last_result` | `OK` |
| `external_last_time` | 建立/更新時間 |

`findOpen()` 視 `external_last_result` 為 null 或不在 `END`、`FAIL`、`CANCEL` 內的任務為 open。

## 6. R031Walker 排程與參數

`R031Walker` 每次排程最多處理一筆 R031 inbox。

```text
app.worker.r031.interval-ms = 1000
app.worker.r031.enabled = true
app.worker.r031.lock-ttl-seconds = 120
app.worker.r031.backoff-seconds = 15
spring.application.name = r031-walker
app.worker.site15.pair-code = SITE15_16
app.worker.site15.expected-target = Site#16
app.worker.site15.device-id = 1
app.worker.site15.crane-id = 1
app.worker.r031.reason = R031_WALKER
app.worker.r031.origin-ttl-seconds = 600
```

撿取 inbox 使用：

```java
pickOneForProcessingByCmdNoNextAttemptTime("R031", workerId, lockTtl)
```

也就是 R031 Walker 會忽略 `next_attempt_time <= NOW()` 條件，只要該筆符合可撿取狀態與 lock 條件，就可能被撿起。

## 7. R031Walker 前置檢查

Walker 在撿 inbox 前會先檢查現場是否可派任務：

1. `Site#15` 有容器時直接 return，不撿 inbox。
2. `Site#16` 有容器時直接 return，不撿 inbox。
3. `Transfer#6` 有容器時直接 return，不撿 inbox。
4. 天車忙碌時直接 return，不撿 inbox：
   - `crane_request` 中指定 `deviceId` 有未完成 request。
   - 或 `crane_task` 中指定 `craneId` 有未完成 task。
5. 查不到 `site_bidir_route.pair_code == SITE15_16` 時直接 return，不撿 inbox。

若以上都通過才會撿 R031 inbox。

## 8. R031Walker 主流程

### 8.1 無 inbox

若沒有可處理的 R031 inbox：

1. 呼叫 `resetActiveTarget(route, expectedTarget, Site#15)`。
2. 若 route 的 `active_target` 為 null 或等於 `expectedTarget`，會改成 `Site#15`。
3. 結束本輪。

### 8.2 inbox 基本檢查

撿到 inbox 後：

1. 若 `cmd_id` 不是 R031：
   - 嘗試將 `active_target` reset 回 `Site#15`
   - requeue 1 秒
   - 結束
2. 依 `inbox.log_id` 查 `robot_in_r031`。
3. 若找不到主檔：
   - reset active target
   - requeue `backoffSeconds`
   - 結束
4. 取出 `carrierId`、`wipName`、`lotId`。
5. 若 `carrierId` 或 `wipName` 為空：
   - reset active target
   - requeue `backoffSeconds`
   - 結束

### 8.3 ZIPA 分支

Walker 先呼叫 `verifyZipaSlotHasCarrier(wipName, carrierId)`：

1. 查 ZIPA all slots。
2. 只看 `type == 3`。
3. 找 `name == wipName` 的 slot。
4. carrier 取 `message[1]`。
5. 若 `message[1] == carrierId`，代表該 carrier 已在 ZIPA 指定 slot。

若 ZIPA 驗證通過：

1. 送 `zipCommandService.sendDispatchOrderSingle(ZipTarget.ZIPA, carrierId, "REJECT")`。
2. 回覆 R031 ACK=`START`，`RESULT_MESSAGE=dispatch created`。
3. 將 inbox mark done。
4. 結束流程。

若 ZIPA DispatchOrder 發送失敗：

1. inbox requeue `backoffSeconds`。
2. 結束。

### 8.4 WIP/STK 出庫分支

若 ZIPA 驗證未通過，Walker 會改走本地 WIP/STK 出庫流程：

1. 查目的地 `LocationPoint.name == Site#15`，取得 `toId`。
2. 若找不到 `Site#15`：
   - reset active target
   - requeue `backoffSeconds`
   - 結束
3. 找容器：
   - 優先用 `container_main.alias_code == carrierId`
   - 找不到且 `lotId` 不為空時，用 `container_main.lot_no == lotId`
4. 若找不到容器：
   - reset active target
   - inbox mark cancelled
   - 結束
5. 查 `location_tracking` 取得該容器目前 `fromLocationId`。
6. 若沒有位置追蹤：
   - reset active target
   - requeue `backoffSeconds`
   - 結束
7. 呼叫 `reservationOrchestrator.reserveOriginForOutbound` 保留來源位置：
   - `containerMainId = c.id`
   - `fromLocationId`
   - TTL 目前傳入 `0`
   - reason 固定 `R031_WALKER`
   - action 固定 `HOLD_ORIGIN_BEFORE_OUTBOUND`
8. 若保留失敗或保留紀錄的 container 不符：
   - reset active target
   - requeue `backoffSeconds`
   - 結束
9. 重新查 `site_bidir_route`。
10. 呼叫 `resetActiveTarget(route, Site#15, expectedTarget)`：
    - 若 `active_target` 為 null 或 `Site#15`，會改成 `expectedTarget`，預設為 `Site#16`。
    - 目前程式即使這個方法回傳 false，也只 requeue，沒有 return，仍會繼續後續流程。
11. 查 ZIPA dispatch status。
12. 若 response/body/statusInfos 為 null，直接 return。
13. 若任一 `type == 5` 且 status 為 `61` 或 `62`，直接 return。
14. 建立出庫 request：
    - `containerMainId = c.id`
    - `fromLocationId`
    - `toLocationId = Site#15`
    - `reason = R031_WALKER;pair=SITE15_16;active=<原本 activeTarget>`
15. 建立成功後：
    - 回覆 ACK=`START`
    - inbox mark done

若建立出庫 request 失敗，inbox requeue `backoffSeconds`。

## 9. active_target 規則

`resetActiveTarget(route, source, target)` 的邏輯如下：

```java
if (route.getActiveTarget() == null || route.getActiveTarget().equals(source)) {
    route.setActiveTarget(target);
    siteBidirRouteRepository.update(route);
    return false;
}
return true;
```

使用位置：

| 情境 | source | target | 目的 |
| --- | --- | --- | --- |
| 沒有 R031 inbox 或異常回復 | `expectedTarget` | `Site#15` | 將雙向區域切回可往 Site#15 的方向 |
| WIP/STK 出庫前 | `Site#15` | `expectedTarget` | 將方向切到預期目標，預設 `Site#16` |

注意：WIP/STK 出庫前呼叫失敗時，目前程式會 requeue 但沒有中止，因此仍可能繼續建立出庫 request。

## 10. ACK 規格

DTO：`R031AckPayload`

### 10.1 ACK 共用欄位

| 欄位 | 值 |
| --- | --- |
| `CMD` | `ROBOT` |
| `CMD_ID` | `R031` |
| `TID` | 原始 R031 COMMAND TID |
| `ID_DESC` | `STK_MOVE_SCH_TO_MANUAL_PORT` |
| `MESSAGE.LOT_ID` | 任務 lotId |
| `MESSAGE.CARRIERID` | 任務 carrierId |
| `MESSAGE.WIPNAME` | 任務 wipName，取消時若 `manualPort` 有值則使用 `manualPort` |

### 10.2 RESULT

| RESULT | 來源 | 說明 |
| --- | --- | --- |
| `OK` | `R031CommandHandler` | COMMAND 驗證通過並成功入隊 |
| `FAIL` | `R031CommandHandler` | 欄位不足、slot 不存在、carrier 不符、DB 寫入失敗 |
| `START` | `R031Walker` | ZIPA REJECT 或 WIP/STK 出庫 request 已建立/送出 |
| `END` | `ZipStockerEventService` | ZIP/TO 成功事件後，找到相同 carrier 的 open R031 任務並完成 |
| `CANCEL` | `RobotTaskCommandController` | 人工取消任務 |

## 11. R031 END 流程

`ZipStockerEventService.tryFinalizeR031IfAny` 在 ZIP/TO 成功事件後執行：

1. 從事件解析 `carrierId`。
2. 查 `robot_r031_task.findOpen()`。
3. 找第一筆 `carrier_id` 等於事件 carrierId 的任務。
4. 若找不到，略過。
5. 若找到：
   - 建立 R031 ACK，`RESULT=END`，`RESULT_MESSAGE` 空字串。
   - 發送到 ASE。
   - 更新 `robot_r031_task`：
     - `external_last_result = END`
     - `external_last_time = now`
     - `internal_state = COMPLETED`
     - `updated_time = now`

## 12. 取消流程

UI/API 取消 R031 任務時：

1. 依 task id 查 `robot_r031_task`。
2. 若任務已是終態，略過。
3. 更新任務：
   - `external_last_result = CANCEL`
   - `external_last_time = now`
   - `internal_state = CANCELLED`
4. 回覆 ACK=`CANCEL` 給 ASE。
5. `RESULT_MESSAGE` 使用取消原因。

終態判斷包含 `END`、`FAIL`、`CANCEL`。

## 13. 會重試、取消或等待的條件

| 條件 | 處理 |
| --- | --- |
| `Site#15` / `Site#16` / `Transfer#6` 任一有容器 | 直接 return，不撿 inbox |
| 天車有未完成 request/task | 直接 return，不撿 inbox |
| 找不到 `site_bidir_route` | 直接 return，不撿 inbox |
| 沒有 R031 inbox | reset active target 後 return |
| inbox `cmd_id` 非 R031 | requeue 1 秒 |
| 找不到 `robot_in_r031` | requeue `backoffSeconds` |
| `carrierId` 或 `wipName` 空白 | requeue `backoffSeconds` |
| ZIPA REJECT 發送失敗 | requeue `backoffSeconds` |
| 找不到 `Site#15` location | requeue `backoffSeconds` |
| 找不到容器 | mark cancelled |
| 容器沒有 location tracking | requeue `backoffSeconds` |
| 來源位置 reservation 失敗 | requeue `backoffSeconds` |
| ZIPA dispatch status response/body/statusInfos 為 null | 直接 return，未 requeue |
| ZIPA dispatch status 有 type=5 且 status=61/62 | 直接 return，未 requeue |
| 建立出庫 request 失敗 | requeue `backoffSeconds` |
| 未捕捉例外 | requeue `backoffSeconds` |

## 14. 目前程式碼注意事項

1. `app.worker.r031.origin-ttl-seconds` 有設定欄位，但 `reserveOriginForOutbound` 目前傳入 TTL 是 `0`，沒有使用 `originTtlSeconds`。
2. ZIPA type=3 carrier 實際讀取 `message[1]`，不是 `message[0]`。
3. WIP/STK 出庫前 `resetActiveTarget(route, Site#15, expectedTarget)` 若回傳 false，目前只 requeue，沒有 return，後續仍可能建立出庫 request。
4. ZIPA dispatch status 查詢異常為 null 或 type=5 status 61/62 時，Walker 直接 return，沒有 mark done 也沒有 requeue；該 inbox 會依 lock 到期後再被撿起。
5. `R031Walker` 發 START ACK 與 mark inbox done，但沒有把 `robot_r031_task.internal_state` 更新成 `PROCESSING`；任務仍依 `external_last_result=OK` 被視為 open，直到 END/CANCEL/FAIL。
6. 找不到容器時目前 mark cancelled，但沒有同步將 `robot_r031_task.external_last_result` 更新成 `CANCEL` 或 `FAIL`。
