# R029 流程規格

產出日期：2026-06-23

## 1. 目的

R029 用於處理拆併打帶相關搬送流程。系統收到 R029 COMMAND 後，會建立 R029 任務與 LOT 清單，由 `R029Walker` 逐顆 LOT 建立出庫任務，將來源載具送往 `Site#9`。R029 任務會依公蓋區狀態、天車狀態、Site#9 狀態與 LOT 是否仍在倉內來決定是否派工。

## 2. 主要程式

| 類別 | 職責 |
| --- | --- |
| `R029CommandHandler` | 接收 R029 COMMAND，驗證 COUNT / CARRIER_LIST，寫入 R029 主檔、LOT 明細、任務表與 inbox，回覆 ACK=OK/NG |
| `R029Walker` | 從 `mqtt_inbox` 取 R029 任務，分配 lane，送 START ACK，逐顆 LOT 建立出庫 request 到 `Site#9` |
| `CoverZoneService` | 讀取 MAIN/SUB 公蓋區 snapshot，判斷是否有對應上蓋或錯料號上蓋 |
| `CoverZoneMonitor` | 公蓋區補蓋 / 回收輔助流程 |
| `R029OutputCaptureService` | 追蹤 R029 產出後續狀態，符合完成條件時更新 R029 task 並送 END ACK |

## 3. COMMAND Payload

使用 `R029CommandPayload`。

### 3.1 Header

| 欄位 | 說明 | 必填 |
| --- | --- | --- |
| `CMD` | 固定 `ROBOT` | 是 |
| `CMD_ID` | 固定 `R029` | 是 |
| `TID` | 任務交易序號 | 是 |
| `ID_DESC` | 任務描述，常用 `MOVE_LOTS_TO_DISMANTLE_AND_TIE` | 否 |
| `MESSAGE` | 任務內容 | 是 |
| `RESULT` | COMMAND 階段通常為空 | 否 |
| `RESULT_MESSAGE` | COMMAND 階段通常為空 | 否 |

### 3.2 MESSAGE

| 欄位 | 型別 | 必填 | 規則 |
| --- | --- | --- | --- |
| `CARRIER_LIST` | Array | 是 | 至少一筆有效 `CARRIERID` |
| `CARRIER_LIST[].CARRIERID` | String | 是 | 不可空白；會去重 |
| `COUNT` | String | 是 | 必須可轉為正整數，代表每個 LOT 的 piece count |
| `TRAY_TYPE` | String | 建議必填 | 用於公蓋料號比對 |
| `TRAY_DESC` | String | 否 | tray 描述 |

## 4. R029CommandHandler 流程

1. 取得 `MESSAGE.CARRIER_LIST`，過濾 null / 空白，並去重。
2. 解析 `MESSAGE.COUNT` 為正整數。
3. 若 `COUNT` 無效，回覆 ACK=`NG`。
4. 寫入 COMMAND 到 `mqtt_message_log`，取得 `logId`。
5. 若 `CARRIER_LIST` 為空，回覆 ACK=`NG`。
6. 檢查所有 carrier 是否存在於倉內 STORAGE，對應欄位為 `container_main.lot_no` 或 `alias_code`。
7. 若有 carrier 不在倉內，回覆 ACK=`NG`。
8. 寫入 `robot_in_r029`：
   - `log_id`
   - `count`
   - `tray_type`
   - `tray_desc`
9. 寫入 `robot_in_r029_lot` LOT 明細。
10. 對來源容器附加 R029 context。
11. 建立 `robot_r029_task`。
12. 寫入 `mqtt_inbox`，priority 固定為 5。
13. 回覆來源端 ACK=`OK`。

## 5. R029 任務初始資料

`robot_r029_task` 建立時：

| 欄位 | 值 |
| --- | --- |
| `log_id` | `mqtt_message_log.id` |
| `tid` | R029 COMMAND TID |
| `piece_per_lot` | `MESSAGE.COUNT` |
| `tray_type` | `MESSAGE.TRAY_TYPE` |
| `tray_desc` | `MESSAGE.TRAY_DESC` |
| `lane` | `null`，由 Walker 分配 |
| `internal_state` | `QUEUED` |
| `external_last_result` | `OK` |
| `external_last_time` | 建立時間 |
| `raw_message_json` | R029 MESSAGE 快照 |

## 6. R029Walker 排程與取件

`R029Walker` 預設每 300 ms 執行一次：

```text
app.worker.r029.interval-ms = 300
app.worker.r029.enabled = true
app.worker.r029.lock-ttl-seconds = 15
app.worker.r029.backoff-seconds = 5
```

取件方式：

```java
pickOneForProcessingByCmdNoNextAttemptTime("R029", workerId, lockTtl)
```

取到 inbox 後，所有暫時不可派工的狀況會呼叫 `requeue(inboxId, backoffSeconds)`。

## 7. R029Walker 主流程

R029Walker 每次處理一筆 inbox。

1. 依 `logId` 查詢 `robot_r029_task`。
2. 若找不到 task，將 inbox 標記 `REJECTED`。
3. 若 task 為 terminal 狀態，將 inbox 標記 `DONE`。
4. 若 task 為 `QUEUED`：
   - 呼叫 `decideLane(task)` 決定 `MAIN` / `SUB`。
   - 若無 lane 可分配，requeue。
   - 呼叫 `trySetLaneAndProcessingByLogId` 將 task 更新為 `PROCESSING`。
   - 送 R029 START ACK。
   - 將 inbox priority 更新為 1。
5. 讀取 R029 LOT 清單。
6. 讀取 R029 `pieceCount`。
7. 查詢 `Site#9` 位置 ID。
8. 建立倉內 container id 集合與 blocked container id 集合。
9. 若所有 LOT 都已不在倉內且無未完成任務，呼叫 `markTaskCompletedAndAckEnd`。
10. 檢查阻塞站點與天車忙碌狀態。
11. 檢查公蓋區狀態。
12. 檢查 `Site#9` PLC 狀態是否有效且 standby。
13. 從 LOT 清單挑選下一顆可出庫 candidate。
14. 預約來源位置。
15. 建立 crane outbound request：來源位置 -> `Site#9`。
16. requeue inbox，等待下一輪處理下一顆 LOT。

## 8. Lane 分配規則

目前 `decideLane(task)` 規則如下：

1. 取得 task `trayType`。
2. 查詢目前 `MAIN` / `SUB` 各有幾筆 `PROCESSING` task。
3. 查詢目前同 `trayType` 的 `PROCESSING` task 數量。
4. 查詢倉內 STORAGE 中 `ALL_COVER` 且 `part_no == trayType` 的上蓋數量。
5. 若目前沒有同 `trayType` 的 R029 正在 `PROCESSING`，且倉內對應上蓋數量小於 1，則不分配 lane。
6. 若 `MAIN` 未被占用，分配 `MAIN`。
7. 否則若 `SUB` 未被占用，分配 `SUB`。
8. 兩線都占用時，不分配 lane。

等價邏輯：

```text
if runningSameTray == 0 and coverCount < 1:
    no lane
else if MAIN free:
    MAIN
else if SUB free:
    SUB
else:
    no lane
```

注意：`coverCount` 僅計算倉內 STORAGE 的 `ALL_COVER`，不計算已在公蓋區的上蓋。若已有同 `trayType` 的任務在 `PROCESSING`，會允許跳過此倉內上蓋數量檢查。

## 9. 進入 PROCESSING

分配 lane 後，Walker 呼叫：

```java
taskRepo.trySetLaneAndProcessingByLogId(logId, lane)
```

更新條件：

| 條件 | 說明 |
| --- | --- |
| `log_id` 相符 | 指定 R029 task |
| `internal_state = QUEUED` | 僅 QUEUED 可進 PROCESSING |
| `lane IS NULL` | 僅未分配 lane 可更新 |

更新內容：

| 欄位 | 值 |
| --- | --- |
| `lane` | `MAIN` 或 `SUB` |
| `internal_state` | `PROCESSING` |
| `external_last_result` | `START` |
| `external_last_time` | 當下時間 |
| `updated_time` | 當下時間 |

若更新失敗或發生 `DuplicateKeyException`，會 requeue。

## 10. START ACK

進入 `PROCESSING` 後，Walker 會送一次 START ACK。

重複送出保護：

```java
logService.hasAckStart(tid, "R029")
```

ACK payload：

| 欄位 | 值 |
| --- | --- |
| `CMD` | `ROBOT` |
| `CMD_ID` | `R029` |
| `TID` | inbox TID |
| `ID_DESC` | `MOVE_LOTS_TO_DISMANTLE_AND_TIE` |
| `RESULT` | `START` |
| `RESULT_MESSAGE` | `accepted` |
| `MESSAGE.CARRIER_LIST` | R029 LOT 清單 |
| `MESSAGE.COUNT` | `robot_in_r029.count` |
| `MESSAGE.TRAY_TYPE` | `robot_in_r029.trayType` |
| `MESSAGE.TRAY_DESC` | `robot_in_r029.trayDesc` |

## 11. 派工前置檢查

R029Walker 在建立出庫 request 前，會依序檢查以下條件。

### 11.1 LOT 清單

`robot_in_r029_lot` 必須有至少一筆 carrier id，否則 requeue。

### 11.2 Piece Count

`robot_in_r029.count` 必須大於 0，否則 requeue。

### 11.3 Site#9 位置

必須能由 `locationPointRepo.findByName("Site#9")` 找到位置 ID，否則 requeue。

### 11.4 全部 LOT 是否已出庫

若每個 LOT 對應的 container 都：

- 不在倉內 STORAGE，且
- 不在 unfinished task / unaccepted request 清單中，

則視為 R029 目前在 Walker 層面已無需再出庫，呼叫 `markTaskCompletedAndAckEnd`。

目前 `markTaskCompletedAndAckEnd` 只將 inbox 標記 DONE；更新 task 為 COMPLETED 與送 END ACK 的程式碼在 Walker 中為註解狀態。實際 END 完成主要由 `R029OutputCaptureService` 負責。

### 11.5 阻塞站點

以下位置若有容器，Walker 不派工：

| 位置 |
| --- |
| `Site#9` |
| `Transfer#3` |

### 11.6 天車忙碌

若以下任一成立，Walker 不派工：

| 檢查 |
| --- |
| `crane_request` 中 deviceId=1 有未完成 request |
| `crane_task` 中 craneId=`1` 有未完成 task |

### 11.7 公蓋區狀態

依 task lane 取得 `CoverLane`：

| Lane | Pool | Staging | Transfer |
| --- | --- | --- | --- |
| `MAIN` | `Site#14` | `Site#13` | `Transfer#5` |
| `SUB` | `Site#12` | `Site#11` | `Transfer#4` |

若 task `trayType` 不為空，會檢查該 lane 三個位置：

| 條件 | 結果 |
| --- | --- |
| 有任一上蓋 `part_no != trayType` | requeue，等待 CoverZoneMonitor 回收 |
| 沒有任何上蓋 | requeue，等待補蓋 |
| 有上蓋但沒有 `part_no == trayType` | requeue，等待補蓋或回收 |
| 沒有 mismatch 且有 matching cover | 通過 |

### 11.8 Site#9 PLC 狀態

`Site#9` 狀態必須：

1. 快取存在。
2. `isValidAndComplete(3)` 為 true。
3. `isSiteStandby()` 為 true。

任一不成立則 requeue。

## 12. LOT Candidate 選擇

Walker 依 `robot_in_r029_lot` 的 carrier id 順序挑選下一顆可派 LOT。

比對 container 時依序使用：

1. `container_main.lot_no`
2. `container_main.alias_code`

候選條件：

| 條件 | 說明 |
| --- | --- |
| 找得到 container | 找不到則跳過該 carrier |
| container 在倉內 STORAGE | 不在倉內則跳過 |
| container 不在 blockedIds | 若已有未完成任務或未接受 request 則跳過 |
| 找得到目前 location_tracking | 找不到則跳過 |

第一個符合條件者會被選為本輪 dispatch candidate。

若無 candidate，requeue。

## 13. 建立出庫 Request

挑到 candidate 後：

1. 呼叫 `reservationOrchestrator.reserveOriginForOutbound` 預約來源位置。
2. 預約 owner：`R029_WALKER`
3. 預約 reason：`OUTBOUND_HOLD_ORIGIN`
4. TTL 預設：`app.worker.r029.reserve-origin-ttl-seconds = 600`
5. 若預約失敗，requeue。
6. 呼叫：

```java
craneRequestCommandService.createOutboundRequest(
    containerId,
    fromLocationId,
    site9LocationId,
    "R029_WALKER;lot={carrierId};pieces={pieceCount}"
)
```

建立完成後，Walker 會 requeue inbox，等待下一輪派下一顆 LOT。

## 14. 完成與 END ACK

### 14.1 Walker 層完成判定

Walker 會判斷所有 LOT 是否已不在倉內且不在 blocked 狀態。若成立，呼叫 `markTaskCompletedAndAckEnd`。

目前該方法實作：

```text
只將 mqtt_inbox 標記 DONE
不更新 robot_r029_task 為 COMPLETED
不送 END ACK
```

### 14.2 R029OutputCaptureService 完成判定

R029 後續產出狀態由 `R029OutputCaptureService` 追蹤。它會在以下事件中更新 `R029OutputItem` 狀態：

| 方法 | 狀態 |
| --- | --- |
| `recordStrappingIfBelongs` | `STRAPPED` |
| `markLabeledIfBelongs` | `LABELED` |
| `markInquiryIfBelongs` | `INQUIRY` |
| `markShelvedIfBelongs` | `SHELVED` |
| `markRemovedIfBelongs` | `REMOVED` |
| `markStockOutIfBelongs` | `STOCKED_OUT` |

當判斷該 R029 相關 alias 已不在現場追蹤位置後，會：

1. 將 `robot_r029_task` 從 `PROCESSING` 更新為 `COMPLETED`。
2. 將 `external_last_result` 更新為 `END`。
3. 發送 R029 END ACK。

END ACK 使用原始 R029 base carrier id 清單。

## 15. Requeue 條件總覽

以下情況會 requeue：

| 條件 |
| --- |
| 無法分配 lane |
| 進入 PROCESSING 失敗 |
| LOT 清單為空 |
| pieceCount 無效 |
| 找不到 Site#9 |
| Site#9 或 Transfer#3 有容器 |
| 天車忙碌 |
| task lane 無法轉成 CoverLane |
| 公蓋區有錯料號上蓋 |
| 公蓋區沒有上蓋 |
| 公蓋區沒有對應 trayType 上蓋 |
| Site#9 狀態快取無效 |
| Site#9 非 standby |
| 無可派 LOT candidate |
| 來源位置預約失敗 |
| 建立 request 或流程中發生例外 |

## 16. 注意事項

1. `countProcessingByTrayType` 與 `countSystemCoverByTrayType` 使用 `trayType.equalsIgnoreCase(...)`，若 task `trayType` 為 null，可能造成例外並 requeue。
2. `containerDataRepo`、`COVER_SITE12`、`COVER_SITE14` 目前在 `R029Walker` 中未使用。
3. Walker 的 END 更新與 END ACK 目前為註解狀態，實際完成主要依賴 `R029OutputCaptureService`。
4. `areAllLotsOutOfWarehouse` 目前遇到找不到 container 的 LOT 會 `continue`，因此所有可找到的 LOT 都出庫時，可能判定為完成。
5. lane 分配目前優先 `MAIN`，`MAIN` 忙才考慮 `SUB`。
