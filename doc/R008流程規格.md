# R008 流程規格

產出日期：2026-06-23

## 1. 目的

R008 用於處理 EQP 到 WIP/STK 的搬送任務。系統收到外部 R008 指令後，會完成參數驗證、任務落庫、回覆接收 ACK，並由 R008Walker 將任務轉送給 SEEC 執行。

## 2. 主要程式

| 類別 | 職責 |
| --- | --- |
| `R008CommandHandler` | 接收外部 R008 COMMAND，驗證參數，寫入 `robot_in_r008`、`robot_r008_task`、`mqtt_inbox`，回覆 ACK=OK/FAIL |
| `R008Walker` | 從 `mqtt_inbox` 取 R008 任務，組成轉發 COMMAND 給 SEEC，完成後將 inbox 標記 DONE |
| `R008AckHandler` | 接收 SEEC 回覆的 R008 ACK，更新 `robot_r008_task.external_last_*` 與 telemetry，必要時轉發 ACK 給 ASE |
| `RobotR008TaskRepository` | R008 任務資料存取 |
| `RobotInR008Repository` | R008 原始入站 MESSAGE 資料存取 |

## 3. 入站 COMMAND 格式

CMD payload 使用 `R008CommandPayload`。

### 3.1 Header

| 欄位 | 說明 | 必填 |
| --- | --- | --- |
| `CMD` | 固定 `ROBOT` | 是 |
| `CMD_ID` | 固定 `R008` | 是 |
| `TID` | 任務交易序號 | 是 |
| `ID_DESC` | 任務描述 | 否 |
| `MESSAGE` | 任務內容 | 是 |
| `RESULT` | COMMAND 階段通常為空 | 否 |
| `RESULT_MESSAGE` | COMMAND 階段通常為空 | 否 |

### 3.2 MESSAGE

| 欄位 | 型別 | 必填 | 規則 |
| --- | --- | --- | --- |
| `LOT_ID` | String | 是 | 不可空白 |
| `CARRIERID` | String | 是 | 不可空白 |
| `WIPNAME` | String | 否 | 可為空 |
| `DEST_LOC` | String | 是 | 不可空白 |
| `EQP_PORT` | String | 是 | 不可空白 |
| `DEVICE_NAME` | String | 否 | 可為空 |
| `TRAY_HIGH` | Decimal | 是 | 必須大於 0，小數位最多 3 位 |
| `TRAY_TYPE` | String | 是 | 不可空白，長度最多 64 |
| `BIN_TYPE` | String | 是 | 僅允許 `G`、`B`、`E`、`GOOD`、`BAD`、`EMPTY` |
| `TRAY_NUM` | Integer | 是 | 必須大於等於 0 |
| `MOVE_PRIORITY` | Integer | 否 | 若有值，範圍 0 到 9 |
| `MISSION_TRIP` | String | 否 | 可為空 |
| `ODO` | Decimal | 否 | 可為空 |
| `AMR_SPEED` | Decimal | 否 | 可為空 |
| `AMR_ROBOT_SPEED` | Decimal | 否 | 可為空 |
| `PPKG_BODY_SIZE` | String | 是 | 長度最多 32，僅允許英數、`.`、`_`、`-`、`x/X` |
| `STK_PORT` | String | 視來源 | ASE 來源可不帶；SAA 轉 SEEC 時會帶出 |

## 4. R008CommandHandler 流程

1. 解析並 normalize `MESSAGE`，空白字串轉為 `null`。
2. 執行參數驗證。
3. 驗證失敗時，直接回覆 ACK=`FAIL`，不建立任務。
4. 驗證成功後，寫入 `mqtt_message_log`，取得 `logId`。
5. 檢查是否有重複 open 任務。
6. 非重複時，寫入 `robot_in_r008`。
7. 寫入或更新 `robot_r008_task`。
8. 寫入 `mqtt_inbox`，供 R008Walker 後續處理。
9. 更新 `robot_r008_task.inbox_id`。
10. 回覆來源端 ACK=`OK`。

### 4.1 重複任務判斷

目前判斷 open R008 任務時，符合任一條件即視為重複：

1. `TID` 相同。
2. `CARRIERID` 相同。

重複時回覆 ACK=`FAIL`，`RESULT_MESSAGE` 帶入重複任務資訊。

### 4.2 任務初始狀態

建立 `robot_r008_task` 時：

| 欄位 | 值 |
| --- | --- |
| `internal_state` | `QUEUED` |
| `external_last_result` | `OK` |
| `external_last_time` | 當下時間 |

## 5. Inbox Priority 規則

`MOVE_PRIORITY` 會轉換為 `mqtt_inbox.priority`：

```text
MOVE_PRIORITY 為空 -> priority = 5
MOVE_PRIORITY 有值 -> priority = clamp(10 - MOVE_PRIORITY, 1, 9)
```

priority 數字越小，越優先處理。

## 6. R008Walker 流程

R008Walker 每次處理一筆 R008 inbox。

1. 使用 `pickOneForProcessingByCmdNoNextAttemptTime("R008", ...)` 取出候選 inbox。
2. 若 inbox `CMD_ID` 不是 R008，requeue。
3. 依 `logId` 查詢 `robot_in_r008`。
4. 若找不到 `robot_in_r008`，將 inbox 標記 `REJECTED`。
5. 依 `logId` 查詢 `robot_r008_task`。
6. 建立轉送給 SEEC 的 `R008CommandPayload`。
7. MESSAGE 欄位優先取 `robot_r008_task`，若 task 欄位為空，再取 `robot_in_r008`。
8. 依 STK_PORT 規則決定 `MESSAGE.STK_PORT`。
9. 寫入轉出 COMMAND log。
10. 發布 MQTT COMMAND 給 `seec`。
11. 將 inbox 標記為 `DONE`。

R008Walker 不會建立本地搬送任務，也不會將 `robot_r008_task.internal_state` 改為 `PROCESSING`。

## 7. R008Walker 轉 SEEC 欄位規則

### 7.1 Header

| 欄位 | 值 |
| --- | --- |
| `CMD` | `ROBOT` |
| `CMD_ID` | `R008` |
| `TID` | inbox 的 `tid` |
| `ID_DESC` | `ROBOT_MOVE_EQP_TO_SCH` |
| `RESULT` | 空字串 |
| `RESULT_MESSAGE` | 空字串 |

### 7.2 MESSAGE

| 欄位 | 來源 |
| --- | --- |
| `LOT_ID` | task.lotId，否則 robot_in_r008.lotId |
| `CARRIERID` | task.carrierId，否則 robot_in_r008.carrierId |
| `WIPNAME` | task.wipName，否則 robot_in_r008.wipName |
| `DEST_LOC` | task.destLoc，否則 robot_in_r008.destLoc |
| `EQP_PORT` | task.eqpPort，否則 robot_in_r008.eqpPort |
| `DEVICE_NAME` | task.deviceName，否則 robot_in_r008.deviceName |
| `TRAY_HIGH` | task.trayHigh |
| `TRAY_TYPE` | task.trayType |
| `BIN_TYPE` | task.binType |
| `TRAY_NUM` | task.trayNum |
| `MOVE_PRIORITY` | task.movePriority |
| `PPKG_BODY_SIZE` | task.ppkgBodySize |
| `STK_PORT` | 依 STK_PORT 規則產生 |

目前 `MISSION_TRIP`、`ODO`、`AMR_SPEED`、`AMR_ROBOT_SPEED` 不由 Walker 轉送。

## 8. STK_PORT 規則

目前 R008Walker 的 STK_PORT 決策如下：

```text
若 task.binType == "B"：
    STK_PORT = "STK05"
否則：
    若 task.stkPort 不為空，使用 task.stkPort
    若 task.stkPort 為空，使用 "STK03"
```

註：程式內原測試用強制 `STK04` 已註解，不列入正式規格。

## 9. R008AckHandler 流程

SEEC 回覆 R008 ACK 後：

1. 記錄 ACK 到 `mqtt_message_log`。
2. 依 `TID` 查詢最新 `robot_r008_task`。
3. 若找不到 task，只記錄錯誤，不再處理。
4. 從 ACK MESSAGE 更新 telemetry：
   - `MISSION_TRIP`
   - `ODO`
   - `AMR_SPEED`
   - `AMR_ROBOT_SPEED`
5. 若 `RESULT` 為 `START`、`FAIL`、`CANCEL`、`END`，更新：
   - `external_last_result`
   - `external_last_time`
   - `fail_reason` 或 `cancel_reason`
6. 若 `app.external.forward-r008-enabled=true`，將 ACK 轉發給 ASE。

## 10. ACK Result 規則

| RESULT | DB 更新 | 是否可轉發 ASE |
| --- | --- | --- |
| `START` | 更新 `external_last_result=START` | 是 |
| `END` | 更新 `external_last_result=END` | 是 |
| `FAIL` | 更新 `external_last_result=FAIL` 與 `fail_reason` | 是 |
| `CANCEL` | 更新 `external_last_result=CANCEL` 與 `cancel_reason` | 是 |
| 其他 | 僅記錄 log / telemetry | 否 |

`CANCLE` 會被正規化為 `CANCEL`。

## 11. 資料表落點

### 11.1 robot_in_r008

保存入站 R008 MESSAGE 主資料，PK 為 `log_id`。

### 11.2 robot_r008_task

保存 R008 任務狀態與轉送所需欄位。

主要狀態欄位：

| 欄位 | 說明 |
| --- | --- |
| `internal_state` | 內部任務狀態，目前建立時為 `QUEUED` |
| `external_last_result` | 外部最新回覆狀態，例如 `OK`、`START`、`END`、`FAIL`、`CANCEL` |
| `external_last_time` | 外部最新回覆時間 |
| `fail_reason` | 失敗原因 |
| `cancel_reason` | 取消原因 |

### 11.3 mqtt_inbox

保存待 R008Walker 處理的 inbox 任務。

R008Walker 成功轉發 SEEC 後，會將 inbox 標記為 `DONE`。

## 12. 注意事項

1. R008Walker 不會送本地 START ACK；程式中的 `sendAckStart(...)` 目前為註解狀態。
2. R008Walker 不會更新 `robot_r008_task.internal_state` 為 `PROCESSING`。
3. R008AckHandler 轉發 ASE 的 MESSAGE 欄位目前需確認實作是否已由 task 正確填入。
4. 重複任務目前只要 `CARRIERID` 相同就會拒絕，不再判斷 `DEST_LOC` 或 `EQP_PORT`。
